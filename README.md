# 飞书 OpenClaw 赛道：企业级长程协作 Memory 系统

## 课题概览：企业级记忆引擎的构造与应用

### 【课题背景】
在日常办公与研发场景中，大模型往往存在“易失忆”的问题。即便模型具备强大的推理能力，每次对话也通常是“从零开始”。本课题不设标准答案，要求参赛队伍扮演**“架构师兼产品经理”**的角色，利用 OpenClaw、CLI 和飞书生态场景，解决以下三个核心挑战：

* **挑战一：重新定义“记忆” (Define it)**
    在企业环境下，什么是真正有价值的“个人/团队记忆”？是 CLI 的高频命令、飞书文档里的架构设计、群聊里的审批习惯，还是用户的隐式偏好？
* **挑战二：构建记忆引擎 (Build it)**
    如何设计一套记忆引擎（Memory Engine），实现记忆的**提取、存储、检索、更新和遗忘**？并确保系统在 CLI 和飞书中无缝流转。
* **挑战三：证明它的价值 (Prove it)**
    如何证明系统真正“记住了”并产生了“实际效能”？参赛者需要自行设计评测用例与指标来验证逻辑。

---

### 【探索方向】
参赛者可任选以下方向，或自行探索其他场景并自证价值。

#### 方向 A：CLI 高频命令与工作流记忆（侧重开发者效率）
* **场景描述：** 开发者在终端中频繁输入长命令、复杂参数或项目路径。系统需自动记录高频模式与偏好，在输入前缀时实现上下文感知的自动补全或推荐（如：在项目 A 推荐参数 X，项目 B 推荐参数 Y）。
* **记忆特征：** 显式记忆（用户主动教学） + 隐式记忆（系统统计频率自动总结）。

#### 方向 B：飞书项目决策与上下文记忆（侧重项目管理）
* **场景描述：** 针对群聊或文档中出现的决策性信息（如方案选择、截止日期确认），系统自动提取决策理由、反对意见与结论，并与时间点关联。在后续讨论触及时主动推送“历史决策卡片”，避免重复争论。
* **记忆特征：** 结构化记忆（决策-理由-结论） + 时序关联 + 主动检索与推送。

#### 方向 C：个人工作习惯与偏好记忆（侧重个性化体验）
* **场景描述：** 通过观察用户行为（点击、命令、日程安排），自动学习其规律（如：周五下午整理周报、会前 5 分钟提醒、偏好表格视图），并在适当时机提供个性化建议或自动化执行。
* **记忆特征：** 隐式学习 + 规则生成 + 主动服务。

#### 方向 D：团队知识断层与遗忘预警（侧重组织协同）
* **场景描述：** 针对易被遗忘的关键信息（如密钥更新、客户偏好），系统允许团队“注入”记忆，并结合**遗忘曲线**（如 Ebbinghaus 模型）在临界点进行群聊复习提醒，同时支持信息的版本覆盖。
* **记忆特征：** 团队共享记忆 + 遗忘曲线 + 版本管理。

### 【交付物要求】
交付内容需包含以下三个核心部分：

1.  **《Memory 定义与架构白皮书》**
    * 明确切入的场景（如 CLI 命令、项目决策等）。
    * 阐述数据流向图及该记忆对企业的核心价值。
2.  **可运行的 Demo**
    * 基于 OpenClaw 和飞书 API 的实际代码。
    * 支持通过 CLI 终端或飞书端进行交互演示。
3.  **自证评测报告 (Benchmark Report)**
    * **抗干扰测试：** 在输入大量无关信息后，系统能否精准捞取一周前注入的关键记忆。
    * **矛盾更新测试：** 先后输入冲突指令（如周报接收人变更），验证系统能否根据时序正确覆写记忆。
    * **效能指标验证：** 量化展示成果（例如：输入字符数减少比例、操作步数缩减等）。
